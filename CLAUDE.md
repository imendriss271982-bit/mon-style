# My Style — notes pour Claude Code

Application de personal styling (PWA statique) avec Aura, styliste IA vocale. Langues : français (source), anglais, arabe qatari. Palette officielle (v120, choix d'Imen) : fond d'écran soie crème (`fond-soie.webp`), couleur d'accent dorée #8C6D35 (v122, `--accent`, icônes, onglet actif) ; TOUS les boutons sont du même doré (`--goldg`, dégradé #A8843F → #8C6D35 → #765A2A, texte blanc), y compris les anciens boutons contour (`.btn.ghost`, `.zf-u-b`, `.gr-man`, `.an-r`, `.zf-big.alt`), cartes blanc pur #FFFFFF, fond secondaire #F5F5F5, lignes #E6E6E6, texte #292421, texte secondaire #6E6E6E. Plus de bordeaux dans l'interface (le bordeaux reste seulement dans les palettes de couleurs proposées aux clientes).

## Structure
- `index.html` : toute l'app (CSS + script principal). Pages = objet `P` (`P.home`, `P.garde`, `P.profil`…), navigation `go(page)` / `back()` / `home()`, rendu `render()`. Barre du bas (v102) : Accueil `home`, Garde-robe `garde` (articles seulement), Aura `chat`, Boutique `boutique`, Profil `profil` (v105 : Boutique remplace Mes tenues ; Mes tenues `tenues` = `P.garde(1)` s'ouvre depuis la garde-robe, l'accueil et Aura). Beauté et Nouveautés s'ouvrent depuis l'accueil ; `DOCK_OF` dit quel onglet reste allumé sur une page secondaire. Un seul écouteur de clic principal (`data-*` sur les boutons).
- `aura-profile.js` : préférences de style choisies par la cliente (`PF`, clé `monstyle_pref`), objectifs, confort, avis 👍/👎, page `P.prefs`, `pfCtx()` (contexte pour Aura), `pfRules()` (règles strictes des prompts), `pfFit()` (classement boutique). Chargé après le script principal.
- `aura-methode.js` : la méthode de stylisme d'Imen (`REF`, une rubrique par ligne, titre en majuscules). C'est ici qu'on met à jour la méthode avec ses cours, sans toucher à `index.html`. Chargé avant le script principal.
- `aura-mesure.js` (v106) : mesure précise du visage. MediaPipe Face Landmarker (chargé depuis jsDelivr + modèle Google, sur le téléphone) place 478 points ; on mesure A (longueur, naissance des cheveux estimée par les tiers du visage), B (front), C (pommettes), D (mâchoire) et l'angularité, puis `classer()` applique les règles du cours d'Imen (seuils dans `SEUILS`). `prepVisage()`/`fixVisage()` dans `index.html` : si la mesure réussit, Gemini reçoit la forme imposée et n'écrit que les conseils ; visage tourné → photo refusée ; mesure impossible (réseau) → ancienne analyse Gemini. `classer()` est testable dans Node.
- `aura-corps.js` (v107) : silhouette sans photo. `CORPS_MES.resultat(mesures)` vérifie hauteur, poitrine, taille, hanches, largeur d'épaules (cm) et classe la silhouette avec la méthode d'Imen (R_WE, R_HE ; seuils dans `SEUILS`) : X · Sablier, A · Poire, V · Triangle inversé, H · Rectangle, O · Ronde, + conseil selon la hauteur. Résultat dans `S.res.corps` avec `src:"mesures"` et `mes` (pas de Kibbe : il se lit sur une photo). Aucune donnée envoyée à l'IA. Testable dans Node.
- Parcours silhouette (v107) : visage → résultat du visage → écran rassurant `b_intro` (3 phrases, Aura dit « Ta photo reste privée… ») → « Prendre ma photo » (`a_body` + appareil ouvert) ou « Je préfère donner mes mesures » (`b_mes`, remplace `a_body`/`c_run` dans le parcours). Lien « Refaire avec une photo » (`data-bphoto`) sur un résultat par mesures. `PR_BODY` : le visage peut être caché ou coupé, Gemini ne refuse jamais pour ça.
- ZIFAFI — My Wedding (espace mariée, v103) :
  - `zifafi-methode.js` : choix du questionnaire mariée (`ZF`), nettoyage (`zfCleanProf`), moteur à règles simples `zfReco(prof,{rej,alt})` → 3 directions distinctes expliquées (ou état « decouverte »), `zfLookOpts` (bijoux, voile, chaussures, coiffure, maquillage, bouquet selon la robe), harmonies `ZF_PALS`. Aucune dépendance au DOM, testable dans Node. La catégorie de silhouette ne sert qu'à départager. Chargé avant le script principal.
  - `zifafi.js` : pages `P.zf` (tableau de bord), `zf_prof` (profil 6 étapes), `zf_robe`, `zf_cmp`, `zf_col`, `zf_look`, `zf_looks`, `zf_insp`, `zf_acad`, `zf_les` ; illustrations SVG originales (`zfDressSVG`, `zfFig`) ; contexte d'Aura `S.zfCtx` (« quotidien » / « mariee », auto selon la page) ; `zfCtx()` ajouté en tête de `PROFIL()` en mode mariée ; `zfHomeCards()` (2 cartes de l'accueil), `zfChatCtx()`/`zfChatSug()` (page Aura). Chargé après `aura-profile.js`.
  - `zifafi-plus.js` (v112, « Zifafi Wedding », chargé APRÈS `zifafi.js`) : entrée renommée « Zifafi Wedding — Ton style de mariée, guidé par Aura. », nouveau tableau de bord (bienvenue, parcours en 7 étapes, 2 actions principales, carte « Ton profil » qui RÉUTILISE `S.res` : visage, silhouette, Kibbe, saison — jamais recopiés ni modifiés ; ce qui manque → `startOnb()` ne lance que les tests manquants), navigation compacte `zfNav` (8 sections, `data-zfgo="page:cat"`). Pages : `zf_dress` (A Aura recommande → `zf_robe` ; B `zf_expl` explorer, choix écrits dans `ZD.prof` ; C photo d'une robe → `S.cphoto` + Aura en mode mariée via le `sendPhoto` existant), `zf_cat` (`S.zfCat` = acc / bouquet / beaute ; options de `zfLookOpts`, choix écrits dans le look en cours `ZD.cur`), `zf_full` (look complet, photo de référence par élément `look.ref`, plusieurs looks, `zfCoherence`), `zf_chk` (checklist `ZD.tasks`, null = liste par défaut non encore modifiée), `zf_tips` (`ZF_TIPS`, recherche, enregistrés `ZD.tipSav`). « J’aime » (`ZD.like`, silhouettes) → `zfRecoProf()` les ajoute aux propositions sans toucher au profil. Formules : `zfCan()`/`ZF_FREE` (1 look gratuit) s'appuient sur `GRATUIT`/`premium()`/`paywall()` existants — vérification sur le téléphone seulement, pas un contrôle de paiement sécurisé.
  - `zifafi.css` : styles de l'espace mariée. `zifafi-i18n.js` : traductions mariée (`ZF_I18N`, même format), ajoutées à `I18N_D` par `i18n.js`.
- `i18n.js` : traductions `[fr, en, ar]`. Toute nouvelle phrase affichée doit y être ajoutée (sinon elle reste en français).
- `worker/worker.js` : Cloudflare Worker (`mon-style.imendriss271982.workers.dev`) qui appelle Gemini (analyses, tenues, make-up) et ElevenLabs (voix). Les clés sont des variables Cloudflare (`GEMINI_KEY`, `ELEVEN_KEY`, `VOICE_ID`, `MODEL`, `IMAGE_MODEL`) — jamais dans le dépôt.
- Assets : `aura-*.webp/jpg`, `videos/`, `sons/`.

## Données (localStorage, sur le téléphone de la cliente)
`monstyle` (profil, résultats), `monstyle_gr` (garde-robe `{items, looks, saved}`), `monstyle_pref` (préférences), `monstyle_plan`, `monstyle_mk`, `monstyle_zf` (ZIFAFI : `{prof, saved, rej, pal, looks, les, prac, insN, like, tasks, tipSav, own, cur}` ; profil mariée : + `budget`, `tenues`, `fleurs`, `bqstyle`). Photos d'inspiration ZIFAFI : IndexedDB `monstyle_zf_img` (réduites à 1024 px, jamais envoyées). Toujours charger avec validation (données abîmées ignorées, jamais bloquantes). Ne jamais migrer de façon destructive. « Effacer toutes mes données » vide aussi `monstyle_pref` et ZIFAFI (`zfWipe()`).

## Règles importantes
- Ne rien inventer sur la cliente : seules ses réponses explicites vont dans le profil.
- Les tenues n'utilisent que les vraies pièces (ids vérifiés) ; un achat proposé est « facultatif ». Pas de marque ni de prix inventés.
- `PROFIL()` résume analyses + infos + `pfCtx()` + `grBrief()` ; c'est la variable `profil` envoyée à l'agent ElevenLabs (voix et chat).
- Accueil (v109) : « Pour toi aujourd’hui » sans photo de vêtements ; cartes Explorer avec vraies photos Unsplash (`HZ_PH`, illustration en secours). Profil, infos et Boutique s’ouvrent sans voix. (v111) Le bonjour d’Aura n’est dit qu’une fois par ouverture : écran d’ouverture OU accueil, jamais les deux, jamais au retour sur l’accueil (`HOME_HI` + `sessionStorage ms_hi`, gardé après un rechargement de mise à jour).
- Accueil (v113, d'après la maquette d'Imen) : en-tête à boutons ronds blancs (profil d'un côté, langue + voix de l'autre), logo « My STYLE » centré jamais traduit (`data-noi18n`), en relief et en deux couleurs (v125 : « My » dégradé or, « STYLE » expresso foncé ; `background-clip:text` + `drop-shadow`, avec padding pour que le « My » manuscrit ne soit jamais coupé ; seulement dans `header` et `#splash`) ; ordre (v121) : salutation + Aura, carte « My Stylist » (Appeler Aura), Mon style (fiche + Outfit check), cartes My Style / Zifafi Wedding, Créer une tenue / Ma garde-robe, « Tes rubriques préférées » (Shopping, Beauté, Looks pour toi), Pour toi aujourd’hui, et « Inspirations du jour » (Nouveautés) tout en bas.
- Fond (v120, choix d'Imen) : soie crème `fond-soie.webp` (son image, non retouchée) PARTOUT : app (`html::before`, `position:fixed`, marche sur iPhone) et écran d'ouverture (`#splash`, boutons caramel, textes foncés). Cartes blanc pur bien encadrées (v123 : effet ambre — bordure miel dégradée #F7D58E → #B9742A en `::after` masqué + halo chaud) ; barre du bas blanc plein ; cercle derrière Aura sur l'accueil retiré ; en mode sombre, fond uni. Arrière-plan dynamique (v126) : la soie ondule lentement (`soieVague`, 26 s, `html::before` et `#splash::before` agrandis de 7 %) et un reflet de lumière passe dessus (`soieReflet`, 11 s, `html::after` / `#splash::after`) ; coupé si « réduire les animations ». (v127-129, vagues amplifiées en v129 car trop discrètes) Imen ne voyait pas l'ondulation : `fond-vivant.js` (chargé en dernier) dessine la soie en WebGL hors écran puis la recopie dans un canvas 2D visible (un canvas WebGL fixe sous une page qui défile s'affichait noir en haut) avec de vraies vagues (déformation sinusoïdale + lumière sur les plis + reflet satiné), ~30 images/s, pause quand l'app est cachée, masqué en mode sombre ; le canvas `#fondVivant` se place dans `#splash` tant qu'il est affiché puis dans `body`. Vidéos d'Aura : détourage du fond vert resserré (~2 px, `glKey`) ; `aura-pose.webp` v2 (bord nettoyé).
